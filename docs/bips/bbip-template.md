```
BBIP: XXXX
Title: Proposal Title
Author: Firstname Lastname <email@example.com>
Status: Draft
Type: Standards Track (Core | Consensus | Networking | Interface | Storage) | Informational | Process
Category: [Omit if Type is not Standards Track]
Created: YYYY-MM-DD
Requires: [BBIP numbers, comma-separated, optional]
```

---

## 1. Abstract
A short (~200 words) description of the technical issue being addressed.

---

## 2. Motivation
The motivation is critical for BBIPs that propose technical changes. It should clearly explain why existing protocol specifications are inadequate and what benefits the proposal provides.

---

## 3. Specification
The technical specification should syntax and semantics of any new feature. The specification should be detailed enough to allow competing, interoperable implementations for any of the current BlockBum platforms.

---

## 4. Rationale
The rationale fleshes out the specification by discussing what alternate designs were considered and related work. It should describe why particular design choices were preferred.

---

## 5. Backwards Compatibility
All BBIPs that introduce backwards incompatibilities must describe how the author proposes to deal with these incompatibilities. This section must state explicitly whether the change is a soft fork or a hard fork.

---

## 6. Reference Implementation
The reference implementation must be completed before any BBIP is given status "Final", but it need not be completed before the BBIP is accepted.

---

## 7. Security Considerations
All BBIPs must contain a section that discusses the security implications and threats relevant to the proposed change. This should include an assessment of potential attack vectors, economic incentives, and mitigations.
